scheduler:  
    - holds uops that has gone through the RAT and got renamed, waiting to be executed
    - executes uop based on the real dependencies, fake ones got removed thanks to RAT, if an instruction (result in s3) is dependent on s1 and s2, it waits for s1 and s2 to be ready(filled) and then executes the next instruction
    - keep IPS in mind, the goal is to have as many instructions running at the same time as possible
    - connected to many execution ports(think of them as channels where you send uops to start them)
    - each port can do only certain ops, one can do add and xor, other on can do load / store
    - you should usually start at the execution ports, they are the hard limit, if you only have two ports that can add, you cannot do more than two adds per cycle, based on this hard limit, you can figure out the other limits
    - load and store are both mov but are different uops(different ports, different speeds of loading / storing)

    - prefetching - array is more predictible(linear or jumping by a constant), can be fixed by allocating elements next to each other, if an array element contains lets say 48 bytes of data, and we fetch 64 bytes, we also fetch part of the next element, this is usually not gonna happen in linked list
    - linked list is a serial dependency
    - if on each node you have alot of computations to do then all of this doesent matter
