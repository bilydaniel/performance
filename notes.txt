Keep the cpu in mind -> instructions in, work out

to make program performant either reduce the number of instructions(simplify the algorithm) or or change the speed at which the instructions go through the cpu(different instructions take different time, or change the order of instructions, or how they access memory)
think about what your code translates into(what asm instructions)

Waste:
    instructions that do literally nothing
    ADD A,B (A += B),LEA A,[B+C](A = B + C), one instruction in cpu, 180 instructions in python

Instructions per clock / instruction level paralelism:
    you can ask the cpu to do the same instruction (ADD) in a way more efficient way
    cpu can do alot more than 1 instruction per cycle
    loop overhead, do more work comparativly to the loop overhead (more sums in one loop), unrolling
    look at the overhead of the work you are trying to do in general, not just loops

    for(int i=0; i < count; i++){
            sum += input[i];
    }

    gets translated into:
        ADD A, input[i]
        ADD A, input[i+1]
        etc...
    -> max is 1 instruction per cycle because it all works on A(the result of the previous add is needed for the next one), need to break the chain up
    serial dependency chain
    cant do instructions in paralel

    for(int i=0; i < count; i+=2){
            sumA += input[i];
            sumB += input[i+1];
    }
    sum = sumA + sumB
    breaks the chain
    cpus have execution ports, each can do certain actions(ADD and CMP can be on the same execution port)
    cpus can only send a certain maximum of instruction per clock(4)
