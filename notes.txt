Instructions per clock / instruction level paralelism:
    you can ask the cpu to do the same instruction (ADD) in a way more efficient way
    cpu can do alot more than 1 instruction per cycle
    loop overhead, do more work comparativly to the loop overhead (more sums in one loop), unrolling
    look at the overhead of the work you are trying to do in general, not just loops

    for(int i=0; i < count; i++){
            sum += input[i];

        ADD A, input[i]
        ADD A, input[i+1]

    serial dependency chain
    cant do instructions in paralel

    for(int i=0; i < count; i+=2){

    cpus have execution ports, each can do certain actions(ADD and CMP can be on the same execution port)

CASHING:
    Very important to performance, analyze them
    ADD A,INPUT[i] -> INPUT[i] is a LOAD, have to wait for it to finish
    Memory is a bottleneck(without cashing)
    To work on anything, the cpu has to have the values in a register file(one of the registers), when loading, the cpu looks into its cashe to load them into the refisters first
    When loading from memory, a cashe line is copied(64 Bytes) usually into all the cashes(L1,L2,L3)
    L1(size = 32KB) speed = 3-4 cycles (64 bytes of data per cycle)
    L2(size = 256KB) speed = 14 cycles 
    L3(size = 8MB) speed = 80 cycles 
    Memory speed = 100+ cycles
    there are prefetch instructions instead of loads to load data into cashe(helps if the load would otherwise be too far for the lookahead, so the cpu doesent know that is gonna need the data and doesent load it ahead, like 300 cycles)
    there si a streaming instruction, that says to never cashe some data, when you know you only gonna need it once
    streaming load / store
    the further away from the cpu the less data per cycle can be retreived(L1 to CPU is like 64 Bytes per cycle, Memory to L3 is like 5 Bytes per cycle)
    imagine connections between cashes like pipes of certain thickness, if your data is mostly in L3 because its too big, it doesent matter that L1 is fast, its waiting to get data from L3
    prefetcher looks at the pattern that accurs in your data loading and tries to guess the next data and prefetches them, whether its linear or skipping by some ammount(//TODO: why do you need data lokality than, ECS should not be better at this case)

    cache alignment helps with not polluting your cache with unneceserry data
    try to always use all the data in the pulled cache line to not waste it(if you are pulling 64B, use all of it, not just a few bytes)
    if data is already loaded in the cache do as much work as possible, so that you dont have to load it again later
    all the leves of cache are the same in terms of hardware, the speed and size differences are just spacial, further away from the core, less connections
    instructions also have caches, L1 is separated for data and instrucitons usually, L2 and L3 are shared
